# Структура проекта obr-mosmit

## Backend

Backend организован по слоям внутри `src/main/java/ru/obr_mosmit/site`:

- `controller` — HTTP/API-контроллеры.
- `service` — бизнес-логика и работа с файлами.
- `service/importer` — импорт данных со старого сайта.
- `repository` — Spring Data JPA-репозитории.
- `entity` — JPA-сущности и enum-модели.
- `dto` — формы и DTO, не являющиеся сущностями базы данных.
- `bootstrap` — одноразовые и условные инициализаторы/импорт-раннеры.
- `config` — конфигурация Spring Security и web-ресурсов.

Старый Thymeleaf-интерфейс администратора удалён. Пользовательский и административный интерфейс обслуживаются React-приложением из `frontend`.

## Frontend

Основные каталоги `frontend/src`:

- `api` — функции обращения к backend API.
- `components` — переиспользуемые компоненты и layout-компоненты.
- `pages` — страницы административного интерфейса и личного кабинета.
- `pages/public` — публичные страницы сайта.
- `styles` — актуальные стили сайта и административного интерфейса.
- `utils` — вспомогательные функции.

Удалены неиспользуемые старые темы `reference-theme`, `editorial-theme`, `responsive-fix`, а также стандартные Vite/React assets, которые не использовались приложением.

## Конкурсы

В текущем интерфейсе конкурса оставлены:

- название;
- срок приёма заявок;
- статус публикации;
- обложка;
- галерея.

Поля старого описания и внешней ссылки на веб-форму убраны из API и интерфейса. Колонки в существующей БД пока сохранены для безопасной совместимости с уже применёнными Flyway-миграциями. Их можно удалить отдельной новой миграцией после подтверждения, что они больше не понадобятся.

## Проверка

TypeScript-проверка frontend выполняется командой:

```bash
cd frontend
npm run build
```

Backend:

```bash
./mvnw clean test
```

Для production используется multi-stage `Dockerfile`: сначала собирается frontend, затем его `dist` копируется в Spring Boot static resources и собирается единый JAR.
